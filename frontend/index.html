System Overview

ORBIT-X architecture from orbital data ingestion to operator-facing APIs.

PIPELINE MAP
DATA & PROCESSING PIPELINE
Current implementation
01 · INPUT
TLE / CelesTrak

Fetch two-line element sets, validate format and epoch, compare versions and preserve update history.

02 · PROPAGATION
SGP4

Calculate satellite position and velocity for a timestamp; persist orbital states for later querying.

03 · TELEMETRY
Simulator

Generate reproducible synthetic subsystem readings and inject faults for repeatable demonstrations.

04 · DETECTION
Threshold rules

Compare readings against configured limits and create explainable alert objects with severity.

05 · STORAGE
MongoDB

Persist satellites, orbital states, telemetry, alerts, missions, ground stations and contact events.

06 · ACCESS
Express REST API

Serve JSON endpoints for records, history, summaries, health checks and alert acknowledgement.

IMPORTANT SCOPE NOTES
Accurate review language
• Telemetry is simulated; this is not a spacecraft downlink receiver.
• Anomaly detection is threshold-based, not trained predictive ML.
• The orbital scene is an illustrative UI visualization, not a precision 3D globe.
• Position conversion includes an approximate coordinate transformation.
• Repeated engine runs require the configured interval mode.
